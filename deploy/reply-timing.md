# 后续回复和北京时间

监控会保留原帖与回复的关联。Codexy 中主帖下的 followups 保留父帖 ID 和上下文；公开镜像发现的新回复会通过 FxTwitter 核验作者和精确帖子 ID，必要时沿回复链最多查找三层父帖。可以经过其他用户的提问，但只推送 Tibo 自己的时间答复；不会把提问者的猜测当作 Tibo 的承诺。

只有能关联到 Tibo 的 Day 系列、Codex/ChatGPT Work 产品计划或额度重置的时间答复才进入推送。回复自己的独立 ID 用于去重，主帖不会随回复重发。父帖暂时取不到时，不把这条时间回复标记为已处理，下次继续补查。每轮父帖查询有数量限制，避免公共接口故障拖住服务。

确定的时间放在 QQ 标题及正文第二行；回复发布时间另行标明。正文第三行翻译答复本身，不把父帖已经完成、他人的提问或猜测混进译文。仅说未来时间不意味着已经完成。

- in two hours：以答复的发布时间加两小时，不按抓取时间计算。
- within the next 2 hours：换算为北京时间的最晚截止窗口，不声称准确在截止时刻执行。
- today / tomorrow at 8pm PT：以发布时刻在美国洛杉矶当地的日期计算，并处理夏令时。
- EOD PST：按原文字面的 PST 固定 UTC-8，换算到下一当地午夜之前；PT/PDT 不会一律当作 PST。
- 只有今天、今晚、EOD，或者只有 8pm 却没说明时区时，不猜具体北京时间。
- 否定、可能、暂定、多时刻范围、夏令时重复或不存在的时刻，会注明不确定，而非编造一个截止时间。

实例：Day 13 的答复 Landing sometime today by EOD PST，发布于北京时间 2026-10-18 00:21。按原文 PST 换算，窗口为北京时间 10-18 16:00 前；这属于预告。PST 若被作者口语化地当作太平洋当地时间使用，可能有一小时差异，程序会明确标注按原文字面 PST 换算，不私自改成 PDT。

离线预览（不访问翻译接口，不发送、不修改去重状态）：

```sh
python3 main.py --dry-run --sample-post examples/reply-time.json
```

公开镜像和社区监控站可能缺少部分回复；本功能不能保证捕获未被这些来源收录的所有回复。没有使用付费 X API 或 Bearer Token。
